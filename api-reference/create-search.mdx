title: "Create a search"

Send a natural-language `query` and a `results` count from 1 to 100. Thred searches for answers and publishes results with supporting evidence automatically.

The endpoint returns HTTP `202` with a search ID. Read [the search](/api-reference/get-search) to follow progress and [its results](/api-reference/search-results) to retrieve answers. Calls and result processing are automatic.

## Example request

<CodeGroup>
```bash cURL
curl https://api.thred.dev/search \
  -H "Authorization: Bearer $THRED_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "Where can I access historical maps of Toronto, and do I need an appointment?",
    "results": 2
  }'
```

```javascript JavaScript
const response = await fetch("https://api.thred.dev/search", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.THRED_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    query: "Where can I access historical maps of Toronto, and do I need an appointment?",
    results: 2,
  }),
});
if (!response.ok) throw new Error(await response.text());
const search = await response.json();
console.log(search.id);
```

```python Python
import json
import os
from urllib.request import Request, urlopen

request = Request(
    "https://api.thred.dev/search",
    method="POST",
    headers={
        "Authorization": f"Bearer {os.environ['THRED_API_KEY']}",
        "Content-Type": "application/json",
    },
    data=json.dumps({
        "query": "Where can I access historical maps of Toronto, and do I need an appointment?",
        "results": 2,
    }).encode("utf-8"),
)
with urlopen(request) as response:
    search = json.load(response)
print(search["id"])
```
</CodeGroup>

These examples use the same request in cURL, JavaScript and Python. The JavaScript example runs server-side with built-in `fetch`; Python uses its standard library.

## Optional structured output

Without `output`, each result contains its answer as text in `content`. Add described fields when you also need structured values:

```json
{
  "query": "Where can I access historical maps of Toronto, and do I need an appointment?",
  "results": 2,
  "output": {
    "appointment_required": {
      "type": "boolean",
      "description": "Whether an appointment is required to access historical maps of Toronto."
    },
    "access_details": {
      "type": "string",
      "description": "How to access the maps, including any registration or visit requirements."
    }
  }
}
```

Each field needs a `type` and a nonempty `description` of up to 1,000 characters. Supported types are `string`, `string[]`, `number`, `integer` and `boolean`. Supply at most 20 fields and 12,000 characters of output-definition JSON. Results include structured `output` only when requested. Partial results can omit unsupported fields; `output` can be null when no supported answer is available.

## Search options

| Option | Purpose |
| --- | --- |
| `location` | Add geographic context separately from the query. |
| `language` | Select a language using a tag such as `en` or `fr-CA`. |
| `timezone` | Resolve relative dates such as “today” using an IANA timezone, for example `America/Toronto`. Defaults to `UTC`. |
| `identity` | Describe who the search is on behalf of with `name` and optional `url` and `description`. Defaults to `{"name":"AI assistant"}`. |
| `call_reason` | Use `public` for gathering information for the public, or `customer` for gathering information on behalf of a customer. Defaults to `public`; it does not make results publicly accessible. |
| `webhook_id` | Receive [webhook events](/guides/webhooks) through an enabled endpoint in the same workspace and environment. |
| `metadata` | Save a custom JSON object with the request, up to 4,000 UTF-8 bytes. It is not echoed in public responses or webhook events. |

## Limits and retries

`results` accepts 1–100 and caps call attempts to distinct sources. Unanswered calls and negative answers count, so the number of complete answers may be smaller. Each workspace/environment can have at most 20 unfinished searches. Request bodies are limited to 64 KiB; the field reference on this page lists individual limits.

To retry safely, set an `Idempotency-Key` when you first submit a request. Reuse that key with the same request after a network timeout or temporary server error. Acceptance can occur before the response reaches you; a retry returns the existing search's current state rather than starting more work.

Keys are scoped to the workspace and environment. A different request with the same key returns HTTP `409`. Use a new key for new work. Omitting the header creates a new search for each POST; the examples above do not perform automatic retries.

HTTP errors contain `error.code` and `error.message`. An HTTP `202` means the search was accepted; follow its status to learn the final result.

The search has a 30-minute dialing deadline. At that point, queued work is canceled and active calls are asked to stop. Already published answers remain available, and result processing can finish after the deadline.
