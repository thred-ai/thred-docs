Read supported answers from `records[].content`. Each record has a stable `rcd_` ID, source details, supporting evidence and call timing.

Every GET returns the full current set of records in relevance order. Replace the previous snapshot or reconcile by record ID. Continue polling only while the search is `running`.

Results are not paginated. Sending `cursor` or `limit` returns HTTP `400` with `error.code: "unsupported_parameter"`.

## Answers and sources

Sources without supported answers are omitted. An answer can cover some requested facts while leaving others unknown. A negative answer, such as “We don't carry that product,” is still an answer.

Records have no individual status or error. The top-level [search status](/api-reference/get-search) indicates whether work is ongoing or has finished with answers.

## Timing

System durations and evidence offsets use **milliseconds**. Calendar timestamps use ISO strings.

| Timing | Field and meaning |
| --- | --- |
| Search accepted | `timestamp`: when the search was accepted. |
| Search duration | `duration`: elapsed time, fixed when the search settles. May be `null` for older searches. |
| Call duration | `source.call_metadata.duration`: pickup-to-hangup time. `null` when unavailable; `0` for a confirmed unanswered call. |
| Call placed | `source.call_metadata.placed_at`: when the source was called, or `null` when unverified. |
| Call pickup | `source.call_metadata.picked_up_at`: when the call was answered, including by an automated menu or voicemail. Omitted when unknown. |
| Quote offsets | `source.evidence[].start` / `end`: offsets from the call's transcript clock. Either may be `null` when unavailable. |

Evidence offsets are not relative to `placed_at` or necessarily to the recording's start. Timing can become more precise on a later read without changing the answer, final status or settled search duration. [Webhooks](/guides/webhooks) are not resent for timing updates.
